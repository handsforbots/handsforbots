# Security

H4B lets software (an LLM, a rule-based bot, an external browser agent) act on a live user session. Treat every action call as untrusted input.

- **Only registered actions run.** There is no `window[...]` lookup or code from messages (v1's action tags are gone). Arguments are validated against the action's schema before the handler runs: `input` (Standard Schema) or, for actions with only `parameters`, the JSON Schema subset H4B emits (`type`, `enum`, `const`, `required`, `properties`, `additionalProperties`, `items`, numeric, length and item limits; `pattern` and other keywords are ignored, so check them in the handler). A failure is `invalid_args`.
- **Origins.** Calls come from `user` (menu, buttons, `runAction`), `assistant` (tool calls of your backend) or `agent` (WebMCP). Use `exposeTo` to limit who sees and calls an action; `expose-webmcp` publishes only actions that explicitly include `'agent'`.
- **Confirmation.** `destructive: true` (or `confirm: 'always'`) asks the `confirm` service for every origin. Without a `confirm` service, such calls are refused.
- **Each call runs once.** A call id runs at most once per conversation: if a transport repeats an `action.call` (a retried stream, a backend that replays its tool calls), the repeat is ignored and the kernel emits `error` with `source: 'action.call'`. Backends must give every tool call its own id, as LLM providers and AG-UI do. The last 1000 ids are kept in the saved session (`seenCallIds`), so a repeat still is ignored after `memory` trims old messages or after a reload. Handlers get the id as `ctx.callId`; pass it to your API as an idempotency key when an action writes on the server, so a retry there doesn't write twice either. This protects against replays, not against a hostile backend, which can always send a new id: keep sensitive actions behind `exposeTo` and `confirm`.
- **Retrieved content (RAG).** Sources and citations are only displayed; they never trigger actions. A document that tells the model to act still reaches H4B as an ordinary `assistant` tool call, so the defense in the page is the same as for any call: `exposeTo` keeps sensitive actions away from the assistant, and `destructive`/`confirm` puts a person in the loop. Keeping retrieved text apart from instructions and checking what the model outputs is the backend's job.
- **State, messages and apps from the backend.** A backend can only write into messages of its own turn: a `message.delta`, `message.part`, `action.call` or `ui.render` whose `messageId` points at a user message, a tool message or an older answer goes to a new assistant message instead, with an `error` (`source: 'stimulus'`). `state.patch` (JSON Patch, `STATE_DELTA` in AG-UI) walks only the state's own properties and refuses paths with `__proto__`, so a patch cannot reach `Object.prototype`; it follows RFC 6902 strictly (array indices are plain decimals, `-` only in `add`, `replace`/`remove`/`test` need an existing target) and takes at most 1000 operations and 32 path segments. A saved or synced session is checked (`parseSessionSnapshot`) before it is restored; a malformed one is refused with `error` and the conversation stays as it was. An MCP App can only send messages as if it were the user (`ui/message`) or add context for the model (`ui/update-model-context`) if you turn that on (`allowMessages`, `allowModelContext`); both are prompt-injection paths, so do it only for apps you trust. Its CSP blocks loading and form posts but cannot stop the app from navigating its own frame, so the bridge closes on navigation; keep `allowTools` short and check links with `confirmLink`.
- **Responses from the backend.** Transports cap what they buffer (one SSE event at 1 MiB, an HTTP body at 10 MiB) and scan streams in linear time, so a hostile or broken backend cannot freeze the tab. What the person sees on a failure is generic (`Backend error (HTTP 502)`), never the response body; operators find it in `error.detail`. Cue data kept in the history is checked again against your vocabulary when it is read back. `openAICompatible` treats only `localhost`, `127.x.x.x` and `::1` as local (`localhost.evil.com` is not).
- **Interceptors.** `action.before` can veto or rewrite any call (rate limits, business rules); `request.before` can redact data before it leaves the browser; `storage.before` before it is stored (`redact` from `@handsforbots/consent`); `signal.before` can drop input.
- **Secrets.** Keys never belong in the browser. Use `httpSTT`/`httpTTS`, `websocketSTT` with short-lived tokens, `universalLLM` or `http` pointing at your backend. `openAICompatible` warns when a key is used outside localhost.
- **Voice effects on a server.** `toFFmpeg` validates the chain and throws on any problem (ranges, at most 32 effects), so a chain from a request cannot add filters such as `amovie` that read files. Run `execFile('ffmpeg', args(input, output))`, never a shell; `command()` is deprecated. See [FFmpeg](./speech.md#ffmpeg).
- **Rendering.** The widget escapes all text and renders a small Markdown subset; links are limited to http(s), mailto, tel and relative URLs (`//host`, `/\host` and their percent-encoded forms count as absolute and are refused; `links.hosts` limits absolute ones to a list); a text over 100,000 characters is shown as plain text, and a citation that ends inside a link or inline code is placed right after it; images (image parts and the gallery) must be http(s), `blob:`, relative or base64 data of a raster type (PNG, JPEG, GIF, WebP, AVIF, BMP), so SVG data URLs are dropped, and the gallery links only http(s) and relative images. `ui.render` components are looked up by own name only, so a name like `constructor` renders nothing. Custom renderers receive props from the backend: treat them as untrusted. Source links are stricter: only absolute http(s) URLs without credentials or same-page anchors, never relative paths (`safeSourceUrl`, optional host allowlist); source titles and excerpts are always text. See [Sources and citations](./sources.md#security).
- **Declarative HTML.** `gui()` reads `data-h4b-say`/`data-h4b-command`/`data-h4b-context` only with `declarative: true`, and only on clicks the person made. Sanitizers such as DOMPurify keep `data-*` attributes, so with it on, HTML you don't control (CMS content, user posts, an app's output) can carry a button that runs one of your actions as `user` or speaks for the person. Turn it on only where every such attribute is yours, and limit it with `root`. The route goes as context without query and hash, and the selection only with `selection: true`.
- **Menu and guided tours.** Typed commands only match input from the chat surfaces, voice, shortcuts and `h4b.send` (`menu({ sources })`), so text an MCP App or the page sends as the user cannot fire them. The assistant points at elements by name (`data-h4b-target`), not by CSS selector, and gets the same answer whether or not the element exists, so it can neither read the page through selector probes nor reach the widget.
- **Keyboard.** Shortcuts ignore synthetic events, IME composition and editable fields (Escape and Alt+M belong to the field there).
- **Privacy.** `observability` does not record message content unless `includeContent: true`: without it, errors keep only `name`, `code`, `stage` and `source`, voice and cue events keep structural fields only, and the browser (`client.environment`) is recorded only with `clientEnvironment: true`. `withFetch` sends trace headers to the same origin only unless `propagateTo` allows more. Sensors and camera are opt-in and show their state; `storage-local` keeps the conversation in the browser, encrypted with a key that expires (a cookie, or your backend with `backendKey`), so it stops being readable after the deadline; for shared devices pick the `'tab'` retention or a short TTL, or keep it on the server with `storage-backend`. This encryption **does not protect against XSS**: a script on the page can read the key and `h4b.messages`. An end-to-end XSS review is a priority in the ROADMAP. See [Persistence, memory and privacy](./persistence.md).
- **Consent.** With `createH4B({ consent })`, storages run only while the person allows it, and withdrawing consent erases what they kept. Decisions come from your consent tool; the presets are not legal advice. See [Consent](./consent.md).
